# Cloud configuration (opt-in)
Use a dedicated Easy3DHome Supabase project; never reuse another product database. Apply all numbered SQL migrations under `backend/` in ascending order, using a reviewed migration. In deployed cloud-config.js set window.Easy3DHomeCloudConfig={url:"https://PROJECT.supabase.co",key:"sb_publishable_YOUR_PUBLIC_KEY"}; never expose legacy `service_role` or `sb_secret_…` keys. The client accepts publishable keys and compatible legacy `anon` JWT keys only; invalid/privileged keys disable cloud without making a request. This is a configuration guard, not JWT signature verification or server authorization. If a privileged key was ever embedded in a public file, rotate it at Supabase immediately; rejecting it at runtime does not remove an exposed key. Enable email confirmation, configure legitimate SMTP and redirects, review Auth rate limits, RLS and security advisors. The app uses managed Auth and explicit upload/download, memory-only session and compare-and-swap revision updates. Cloud is disabled by default in unconfigured builds. The separate CI workflow uses a disposable real local Supabase stack; production credentials are not needed. Account-level deletion and production setup must be validated separately.
